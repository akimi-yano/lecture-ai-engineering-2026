## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：具体的な講座のシラバスや直近の指示内容によって多少定義が異なる場合がありますが、AI・プログラミング学習における「3レベル課題」は、通常、受講生の**現在のスキルや理解度に合わせて選べるように用意された「難易度別の課題」を指します。:レベル1（基礎・入門：Basic / Beginner）, レベル2（応用・実践：Intermediate / Standard）, レベル3（発展・挑戦：Advanced / Expert）
- 用語集の正しい意味と比べて気づいたこと：用語集では簡潔にまとめられているのに対し、モデルはかなり助長に内容を付け足して（多分予測して）回答してくれました。
- 表示できたトークン数（入力 / 出力）：（入力）input_tokens=21、 （出力）output_tokens=585

## 宿題

宿題は「基礎」「実装」「発展」の3レベルです。

### 基礎

- 取り組んだレベル：基礎
- やったこと：`LoRAとは何ですか？80字以内で説明してください。` を、モデル `gemini-3.5-flash-lite` のまま temperature `0.2` と `0.8` で各3回実行した。
- 結果：

	| temperature | 回 | 回答の要旨 | 出力トークン |
	|---:|---:|---|---:|
	| 0.2 | 1 | モデル本体を書き換えず少量のパラメータを追加して学習・カスタマイズする手法（75字） | 37 |
	| 0.2 | 2 | 本体を固定し少数の追加パラメータで低コストに特定用途へ最適化する技術（79字） | 46 |
	| 0.2 | 3 | 一部を追加学習する手法と説明。80字以内の指定を超える88字の回答に加え、短縮版も出力した | 119 |
	| 0.8 | 1 | モデル全体を書き換えず少量のパラメータを追加・学習してカスタマイズする技術（77字） | 36 |
	| 0.8 | 2 | 全パラメータを更新せず小さな追加パラメータを学習させる手法（76字） | 33 |
	| 0.8 | 3 | 2回目とほぼ同じ説明で、「手法」を「技術」と表現（77字） | 33 |
- 気づき・疑問：6回答はいずれもLoRAを「モデル全体ではなく少数のパラメータを学習する手法」と説明しており、要点は共通していた。一方、言い回しや付け加える特徴（低コスト、特定用途への最適化）には違いがあった。temperatureが低い条件でも指示どおりの長さになるとは限らず、0.2の3回目は字数制限を超えた。今回の回数だけではtemperatureによる回答の長さや品質の傾向までは断定できない。

### 実装

- 取り組んだレベル：実装
- やったこと：`app/ask.py` に `--interactive` を追加し、同じChatセッションで続けて質問できるようにした。`printf '%s\n' 'LoRAとは何ですか？一文で説明してください。' '先ほどの説明でいう「少量のパラメータ」とは何ですか？' 'exit' | uv run python -m app.ask --interactive` で2問を続けて送信した。
- 結果：1問目はLoRAを「モデル本体を書き換えず、少量のパラメータを追加・学習する技術」と説明した。続く質問では、直前に出た「少量のパラメータ」を受け、モデルの一部に後から加える調整用パーツと説明し、付箋にたとえた。応答時間とトークン数は、1問目が0.62秒・入力13/出力48、2問目が1.34秒・入力76/出力185だった。対話を終了するときは `exit` を入力する。
- 気づき・疑問：2問目で前の回答に出てきた用語を具体的に説明できたため、会話履歴が引き継がれていることを確認できた。2問目は入力トークン数が増えており、会話が続くほど履歴も入力に含まれることが分かった。会話が長くなったときのトークン量や、履歴をどこまで残すべきかが気になった。

### 発展

- 取り組んだレベル：発展
- やったこと：`uv run python -m app.ask --model gemini-3.5-flash --model gemini-3.1-flash-lite "LoRAとは何ですか？80字以内で説明してください。" "RAGとは何ですか？80字以内で説明してください。"` を実行し、2モデル×2質問の応答時間と入出力トークン数を比較した。
- 結果：

	| モデル | 質問 | 応答時間 | 入力トークン | 出力トークン |
	|---|---|---:|---:|---:|
	| gemini-3.5-flash | LoRA | 10.15秒 | 15 | 45 |
	| gemini-3.1-flash-lite | LoRA | 2.74秒 | 15 | 45 |
	| gemini-3.5-flash | RAG | 9.95秒 | 15 | 43 |
	| gemini-3.1-flash-lite | RAG | 2.75秒 | 15 | 48 |

- 2回の平均応答時間はgemini-3.5-flashが約10.05秒、gemini-3.1-flash-liteが約2.75秒だった。回答内容はいずれも用語の要点を説明しており、出力トークン数も近かった。4回とも成功し、429エラーは発生しなかった。
- 気づき・疑問：今回の測定ではgemini-3.1-flash-liteの応答が速かったが、各モデル2回だけの結果であり、通信状況やサービスの混雑にも左右されるため、一般的な速度差とは断定できない。複数条件を試すほどAPIリクエストとトークンの利用量が増えるため、無料枠のレート制限に近づく可能性がある。一方、今回の4回で429が出なかったことだけでは上限は分からず、トークン数から残り枠も判断できない。モデルごとの最新の制限を確認し、429が出た場合は時間を置いて再試行する必要がある。
